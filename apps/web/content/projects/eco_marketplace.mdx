This is my health management and doctor appointment application named **Skin Flirt**, designed to streamline healthcare accessibility and patient management. Alongside Firebase and a custom-built backend API, I implemented the **Provider** package for predictable, reactive state management across the application.

## Features

- **Doctor Discovery & Profiles**: Browse certified medical specialists, view profiles, and check live availability fetched via custom API endpoints.
- **Appointment Booking System**: Reliable scheduling workflow communicating directly with the custom backend to manage reservations seamlessly.
- **Health Records Management**: Securely store and access medical history, prescriptions, and health checkup reports.
- **Real-Time Notifications**: Automated reminders for upcoming appointments and medication schedules.
- **Secure Authentication**: Robust user authentication workflows separating patient and doctor portals.

## Tech Stack

- **Frontend & Mobile**: Built using **Flutter** and **Dart** for cross-platform performance on Android and iOS.
- **State Management**: Utilized **Provider** to efficiently manage application state, handle UI re-renders, and decouple business logic.
- **Backend & API**: Developed and consumed a **Custom-Built Backend API** using HTTP clients (`Dio`) for data communication.
- **Database & Cloud**: Powered by **Firebase** for real-time services, cloud messaging, and authentication.

## Implementation

### Frontend & UI

- Custom **Flutter** widgets tailored for responsive booking calendars and interactive user dashboards.
- Clean separation of presentation layers and model data using ChangeNotifier classes.

### State Management & API Integration

- Implemented **Provider** to manage user sessions, appointment states, and dynamic doctor directories reactively.
- Configured **Dio** for advanced network handling and error management when communicating with the custom API.

## How It Works

1. **User Sign-Up**: Patients create a profile and log in via managed authentication flows.
2. **Specialist Search**: The app fetches doctor directories dynamically through the custom API, updating the UI via Provider.
3. **Seamless Booking**: Selecting a time slot dispatches a request to the backend API, updating local states instantly.
4. **Consultation Tracking**: Receive reminders, view medical records, and track consultation histories synced across the platform.

## Challenges Faced

- Managing asynchronous API states and loading indicators efficiently using Provider without unnecessary UI rebuilds.
- Handling network latency and token-based authentication securely between the Flutter client and the custom API.
- Ensuring real-time synchronization of booking statuses across multiple connected users.

## Future Enhancements

- Integrating in-app video consultation features via WebRTC or Agora SDK.
- Introducing a secure digital payment gateway for online consultation fees.
- Adding an AI-powered preliminary symptom checker to assist with specialist recommendations.
